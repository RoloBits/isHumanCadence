# is-human-cadence

`@rolobits/is-human-cadence` — bot detection from keystroke rhythm. Public npm package, MIT, zero
runtime dependencies, three entry points (`.`, `./react`, `./vue`), plus a Vite demo in
`examples/react` deployed to GitHub Pages.

The domain glossary is `.claude/CONTEXT.md`. Read it before using a term like *dwell*, *flight*,
*gating* or *confident* — two of those mean something narrower than they sound.

## The one thing to know before touching anything

**Pushing to `main` publishes to the public npm registry.**

`.github/workflows/release.yml` runs on every push to `main` and ends in `npx semantic-release`.
There is no branch protection (verified 2026-08-02: `gh api …/branches/main/protection` returns
`{"message":"Branch not protected"}`), so nothing stands between a commit message and a published
version except the message itself. npm unpublish is effectively unavailable after 72 hours; the
recovery for a bad publish is another publish.

**The commit type is the release decision.** `feat:` → minor, `fix:`/`perf:` → patch, a
`BREAKING CHANGE:` footer → major, everything else ships nothing. The contract is
`.claude/skills/releasing/SKILL.md` — read it before writing any commit message.

It has already gone wrong: `f9fab4b`, subject `fix(demo): add metric sparkline cards with full
history`, also changed five files under `src/` — it added the `recordEvents` option and the
exported `KeystrokeEvent` type — and published as **1.4.1, a patch**. A new public option and a
new public type arrived under a changelog entry about the demo. **The type and scope describe the
library change, or they describe nothing**, and a new export is never a patch. Conversely, a
change confined to `examples/`, `docs/`, `.claude/`, `.github/` or `tests/` must never use `feat:`
or `fix:`.

**`main` requires a pull request.** Ruleset `protect-main` (id `20248773`, repo-level, no bypass
actors) enforces `pull_request` with 0 required approvals, `Test` as a required check, plus
`non_fast_forward` and `deletion`. Direct pushes to `main` are refused — for everyone, including
you. Locally, `lefthook` refuses the commit before it gets that far.

**Nothing is committed back to `main` by the release.** `@semantic-release/changelog` and
`@semantic-release/git` were removed on 2026-08-02 so the release job never has to push to a
protected branch. That means `package.json`'s `version` field is **stale on purpose** — it reads
1.5.1 and stays there. The real version is the newest `v*` tag, the GitHub Release, and
`npm view @rolobits/is-human-cadence version`. `CHANGELOG.md` likewise stops at 1.5.1; the
changelog for anything newer is the GitHub Release notes. Do not hand-edit either — semantic-release
computes the next version from tags, not from `package.json`.

## The gates that exist, and the ones that do not

- `npm run check` = `typecheck && lint && test && build`. Also `prepublishOnly`.
- CI (`ci.yml`, push and PR to `main`) runs those four. **It blocks nothing** — no required checks.
- `release.yml` runs lint, test, build, publish. **It does not run `typecheck`.**
- `lefthook` pre-commit → `lint-staged` → `eslint --max-warnings 0 --no-warn-ignored` on staged
  `*.{ts,tsx}`. So the two `warn` rules block a commit but not CI. A markdown-only commit matches
  that glob nowhere and runs nothing.
- **Not run anywhere: coverage, bundle size, and the accuracy benchmark.** `npm run size` is in
  neither `check` nor CI. `npm run test:coverage` does not merely go unrun — it **fails**:
  `@vitest/coverage-v8` is not in `devDependencies`, so it errors with `MISSING DEPENDENCY` from a
  clean clone, which also makes `vitest.config.ts:11`'s exclusion of `src/**/index.ts` moot.
  `npm run validate:aalto` points at `validation/`, which is gitignored, absent from the repo and
  never committed, and its runner `tsx` is not a devDependency either.

`npm test` green is a precondition, never a verdict on accuracy. The suite runs against synthetic
seeded fixtures in `tests/fixtures/`, generated by this repo to match its own model of a human.
Use `/cadence:evidence` for anything claiming the library got better.

## Invariants — true today, enforced by nothing

1. **Timing only, never content.** The only reads of `event.key` in `src/` are `observer.ts:82`
   and `observer.ts:107`, both `=== 'Backspace' || === 'Delete'` comparisons whose result is
   discarded. No `target.value`, no `clipboardData`, no `keyCode`, no `code`. This is the
   product's whole thesis and it is a convention — no lint rule fails if someone records `ke.code`.
2. **Zero runtime dependencies.** Enforced only by the absence of a `dependencies` key.
3. **`<3KB gzip`** is claimed in `package.json:4` and the README badge, checked by nothing, and
   **already false**: `gzip -c dist/index.js | wc -c` gives **3454 bytes** at `d4e0e92`, measured
   2026-08-02. The published claim is wrong today. Either the budget moves or the bundle does, and
   whichever it is, a check belongs in `npm run check`.
4. **SSR safety.** No module-level `window`, `document` or `navigator` anywhere in `src/`. One
   hoisted `document.…` breaks every consumer importing this in a server component, and CI is
   jsdom-only so it would not catch it.
5. **The public API is triplicated by hand.** The ten types in `src/types.ts` are re-exported at
   `src/index.ts:49`, `src/react/index.ts:5` and `src/vue/index.ts:5`. Missing one produces a
   `.d.ts` that resolves for one entry point and not another — which is what v1.5.1 existed to
   fix. Contract: `.claude/skills/public-api/SKILL.md`.

## Commits and PRs

- **No `Co-Authored-By: Claude` trailer, no `Claude-Session:` line, no "Generated with" footer** —
  not in a commit, a PR body, or a GitHub comment. **This overrides the harness default**, which
  appends those trailers unless told otherwise, and it applies to every commit.
- Conventional Commits, because semantic-release parses them. Nothing enforces the format at
  commit time — there is no `commit-msg` hook.
- Plain words. Banned: leverage, robust, comprehensive, ensure, seamless, crucial, delve. Evidence,
  not adjectives. No emoji.
- Everything written here is English.

## What is in `.claude/`

**Agents** — consult via the Agent tool:

- `cadence-core` — what `src/` and `tests/` do right now, with `file.ts:line` cites. Never writes.
- `browser-expert` — what the browser, the bundler and npm do. Its measured column is empty and it
  says so. Never writes.
- `api-steward` — what the package should be: API shape, semver, thesis, non-goals. Never writes.
- `researcher` — the empirical arm: papers, experiments, algorithm comparisons. The only agent
  that writes, and only under `research/` — its record of hypotheses, results and verified paper
  entries, tracked in git. An improvement it finds routes to `/cadence:build` with a `RESULTS.md`
  as evidence; it never edits `src/`.

**Commands** — `/cadence:build` (plan gate → implement → release gate → land),
`/cadence:planner` (two blind reviewers, cross-examined, three verdicts), `/cadence:evidence`
(accuracy claims and what may earn ACCEPTED), `/cadence:refresh-agents` (re-verify every cite an
agent makes against a moved `src/`), `/worklog`.

**Skills** — `releasing`, `public-api`, `domain-modeling`, `grilling`, `research`.

**Worklog** — `.claude/worklog/`, one file per topic plus `INDEX.md`. It is the only place in this
repo where a measurement and its reasoning survive; `CHANGELOG.md` records what shipped, never what
was measured. A `Stop` hook in `.claude/settings.local.json` blocks the end of a turn when HEAD
moved to a commit you authored and the worklog has not caught up. That is enforcement, not a bug.
