# bench — the one command that prices a detection change

```
npm run bench
```

Scores the current working-tree engine (`src/`) against both error types and prints a
stable, greppable report. Requires the CMU corpus (one-time, 4.5MB, gitignored):

```
curl -o research/experiments/2026-08-02-cmu-real-human-baseline/DSL-StrongPasswordData.csv https://www.cs.cmu.edu/~keystroke/DSL-StrongPasswordData.csv
```

If the file is missing the bench fails with that exact command; it never silently skips.
Deterministic: seeded PRNGs, fixed windowing, no `Math.random()`, no `Date.now()`.
Same input, same output, every run.

## What the two numbers mean

- **HUMAN_FP** — the fraction of real human typing windows (CMU Killourhy-Maxion,
  51 subjects, 2448 windows of 88 keystrokes) scoring below the confident-human
  threshold (0.70, `DEFAULT_CLASSIFICATION_THRESHOLDS.unknownToHuman`). These are
  real people a consumer's login form would fail to recognize as human.
- **BOT_FN, per generator** — the fraction of 50 seeded runs of each bot generator
  scoring at or above 0.70. These are bots the engine waves through. The generators
  are the three from `tests/fixtures/bot-profiles.ts`, a replay bot, and a
  **metric-aware forger**: human-shaped log-normal dwells and flights with injected
  corrections and zero rollovers — the adversary that has actually beaten the
  library in the field (`research/field-reports/`).

A change that lowers a BOT_FN while raising HUMAN_FP is a trade, not a win, and the
PR must say so.

## Why `npm test` cannot answer this

The suite runs against synthetic fixtures generated by this repo to match its own
model of a human. Measured (see `research/`): every detection candidate looked free
on the fixtures and cost real humans on the CMU corpus, because the synthetic human
always emits rollovers and never exercises the changed branch. `npm test` green
means the fixtures still behave; it says nothing about accuracy. `npm run bench`
is the accuracy statement a PR can make from a clean clone.

## Worked example — a PR body

The before numbers are the real baseline above; the after numbers are invented
for illustration — the format is the point.

> This PR makes zero rollovers over 40+ keystrokes count as a weak bot signal
> instead of abstaining.
>
> `npm run bench`, before (main) → after (branch):
>
> ```
> HUMAN_FP=0.1675 → 0.1720   (+0.0045: 11 more real windows lose confident-human)
> BOT_FN replayBot=0.9800 → 0.1200
> BOT_FN metricAwareForger=1.0000 → 0.3400
> BOT_FN gaussianBot=0.6800 → 0.0800
> ```
>
> This is a trade: replay-class bots drop from 98% pass to 12%, at the cost of
> 0.45 points of human false positives, concentrated in slow typists who rarely
> overlap keys.

Paste both runs, state the trade. Numbers above the arrow come from `main`, below
from the branch — run the bench on each checkout.
